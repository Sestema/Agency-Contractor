# Agency Contractor 0.1.94 — працівники, архів, звіт, зарплата multi-PC і рахунки

## Працівники
- Стабільніше відкриття вкладки (виправлено краш через невалідний колір у XAML).
- Пігулка фірми: dropdown відкривається нормальним кліком, без «тримати кнопку».
- Верхня панель статистики: рівні блоки, чіткіший текст при масштабі.
- Після збереження анкети список оновлюється точково, без повного перезавантаження.
- При виході з картки працівника коректний Cleanup (менше проблем після PDF).

## Архів
- Оновлення плиток / вигляду карток архіву.
- Стабільніша робота списку та фільтрів.

## Звіт
- Надійніше застосування фільтрів і побудова звіту.
- Коректніше відображення типів документів у зведенні.

## Зарплата — збереження і відкриття
- Відкриття місяця лише читає дані: без тихого full resave / перезапису БД.
- Save зберігає зміни по всіх фірмах; фільтр фірми лише для відображення.
- Після Save очищаються лише реально записані рядки — правки інших фірм більше не губляться.
- «Позначити всі як оплачені / неоплачені» змінює лише рядки, які справді треба змінити.
- Виправлено зависання / шторм помилок «вже змінено на іншому ПК» після cleanup місяця (UpdatedAt синхронізується з UI).

## Зарплата — PostgreSQL і наступний місяць
- «Створити наступний місяць» коректно зберігається в PostgreSQL (оновлюються маркери завантаженого місяця, результат Save перевіряється).

## Аванси і нетто
- Після додавання / видалення авансу рядок стає dirty і потрапляє в Save.
- Якщо нетто вже не збігається з SavedNetSalary — рядок позначається для збереження.
- Після Save Dashboard і Telegram показують правильну суму.

## Sync між ПК
- Запізнілий / старіший remote не перезаписує свіжіший локальний рядок.
- Порівняння UpdatedAt надійніше (парсинг дати).
- Новіший remote з іншого ПК не накатується поверх ваших локальних змін автоматично.
- Editing-lock знімається після завершення WPF commit (ContextIdle) — sync не влітає посеред редагування комірки.

## Перейменування фірми (PostgreSQL)
- Разом із зарплатою оновлюються аванси, accommodations, custom fields, salary reports і шляхи employee_folder.
- Операція в транзакції з можливістю rollback.

## Витрати
- Порівняння назви фірми case-insensitive (як для годин після rename).
- Більше немає ризику: DELETE через lower() + порожній insert через різний регістр (Firma / firma).

## Рахунки-фактури
- Округлення звичайного рахунку (none / whole / half) реально застосовується до суми «до сплати»; PDF і QR отримують ту саму суму.
- Касові документи без змін у своїй логіці округлення.
